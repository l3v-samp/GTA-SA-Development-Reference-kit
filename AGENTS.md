# Development instructions

1. Select the exact runtime first: Pawn SA-MP 0.3.7/open.mp, MoonLoader Lua, MTA Lua client/server, native ASI C++, or Blender assets. Use modules/README.md and its runtime folders. Never mix MoonLoader and MTA APIs.
2. Read modules/PREPARE_REFERENCES.md and modules/REFERENCE_CATALOG.json. Run `python3 modules/prepare_references.py --feature FEATURE` (miner, speedometer, needs, inventory, filterscripts) or `--all --starters` before source inspection. The extractor validates checksums and refuses to overwrite modified files; use a fresh destination for changed snapshots.
3. Pawn references and metadata live in modules/pawn/samp: FEATURE_GUIDE.md, FEATURE_INDEX.json, INCLUDE_AUDIT.json, REFERENCE_FILE_INDEX.tsv, REFERENCE_LOCK.json, DEPENDENCY_REPORT.md, PAWN_LIBRARIES.md, PAWN_SOURCE_LOCK.json and PAWN_FUNCTION_INDEX.tsv. The shared library pack is modules/pawn/samp/pawn-libraries-source.zip. Extract it separately when needed.
4. Inspect actual extracted Pawn source, includes, data enums, callback owners, initialization/cleanup, GUI, timers, persistence, schema and license. Compare at least two implementations when available. The miner routing has one identified mining job plus another gamemode's job architecture; Minerext.pwn is mapping, not job logic.
5. Preserve dependency versions in separate paths. Report unresolved or generated includes and required plugin binaries. DL gamemodes are porting references only; do not claim 0.3.7/open.mp compatibility without adapting and validating the relevant APIs/assets.
6. Implement features with config, data, service, UI and persistence boundaries as applicable. Use one callback owner or the project's existing hook framework. Clean timers, TextDraws, objects, entities and player data at lifecycle exit.
7. New source belongs under projects/<runtime>/<project>/; references and starters belong in their canonical modules runtime folder. Do not create duplicate archives or indexes at repository root or modules root. Shared catalog/extractor/guide remain at modules root.
8. Record upstream commits, adapted source paths, attribution/license, exact tool/runtime versions and validation results. Do not describe an indexed keyword, uncompiled scaffold or extracted source as a working tested system. Pawn needs matching compile/server checks; Lua needs its intended client/server; ASI needs the exact executable and x86 SDK; assets need export/reimport and in-game validation.
9. Keep secrets, player data, runtime binaries, game assets and build caches out of Git. Do not run downloaded upstream code merely to inspect it. Fetch additional references with scripts/fetch_reference.py only when needed.
